II. Software Requirement Specification
1. Product Overview
The Virtual Try-On Uniform System is a web-based platform that allows users—primarily students or online shoppers—to upload a personal photo and try on digital uniforms or outfits virtually. The system aims to improve the online shopping and uniform selection experience by allowing users to visualize how a uniform/outfit would look on them before making a purchase or selection decision.
The system operates as an interactive web application where the user uploads an image, selects clothing items, adjusts the items (scale, position, rotation), and previews the final composite image. The system also provides an admin interface to manage outfits.
Context Summary:
Users interact with the system via a browser.


The system receives image files from users.


The system processes clothing overlays.


Admin users upload and manage outfit assets (uniform images).


Storage system manages uploaded user photos and outfit resources.

Description:
This use case allows a Parent to view detailed information of their current account, including contact details and basic personal settings.
Priority:
Medium
Trigger:
Parents click the “Profile” button on the main navigation bar and select “Account Information.”
Preconditions:
PRE-1: The Parent has successfully logged in to the system.
PRE-2: The account status is Active.
Post-Conditions:
POST-1: The system displays the Account Information interface with all personal data retrieved from the database.
Basic Flow:
5.1 View Account Information tab
The Parent clicks the “Profile” menu at the top-right corner of the screen.
The system navigates to the default Profile page
(or the user selects the “Account Information” tab from the left-side menu).
The system displays the Personal Information form, including:
Avatar (profile picture)
Full Name
Date of Birth (Day/Month/Year)
Gender (Male / Female / Other)
Email and Phone Number (with an Update button)
 The Parent reviews the displayed information.
Alternative Flow:
5.2. Switch to Security Tab
At Step 4, the Parent selects the “Security” tab.
The system navigates to the Password Change / Security Settings screen.
5.3. Missing Data
If fields such as Date of Birth or Gender contain no data (null),
The system displays empty or default values to indicate that the information needs to be updated.
Exception:
5.E1. Connection Error
The system displays MSG10 and advises the user to try again later.

Use Case ID
UC-06
USE CASE NAME
Update Personal Information
Created By: 
HuyenCTT
Date Created:
10/01/2026
Primary Actor:
Parent
Secondary Actor:
None
Description:
This use case allows a Parent to edit their personal profile details, specifically ensuring their name and contact phone number are accurate for delivery and support purposes
Priority:
Medium
Trigger:
The Parent clicks the "Update" button on the Profile page or proceeds through the initial information setup screen
Preconditions:
PRE-1: The Parent has successfully logged in to the system.
PRE-2: The account status is Active.
Post-Conditions:
POST-1: The Parent's information (Name, Phone, Avatar) is updated in the database.
POST-2: A success message is displayed to the user.
Basic Flow:
6.1 Update Information Process
On the Account Information tab, the Parent modifies basic fields: Full Name (Text input), Date of Birth (Day/Month/Year dropdowns), and Gender (Radio buttons: Male/Female/Other). 
Optionally, the Parent clicks the edit icon on the circular Avatar to upload a new picture. 
The Parent clicks the Save Changes button located below the Gender selection. 
The system validates the inputs (e.g., Name is not empty) and updates the basic profile information in the database.
The system displays a success message.
Alternative Flow:
6.2.  Cancel Update
The Parent clicks "Cancel" or navigates away, causing the system to discard any unsaved changes and revert to the previous data.

4. Non-Functional Requirements
4.1 External Interfaces
This system shall interact with the following external systems and interfaces:
Payment Gateway API for processing online payments and refunds.
AI Image Processing Services for background removal, body segmentation, and virtual try-on generation.
Cloud Storage Service for storing uploaded photos and generated try-on results.
Web Browser Interface supporting modern browsers (Chrome, Edge, Firefox).
Optional Mobile Browser Interface for parent users accessing the system on mobile devices.
4.2 Quality Attributes
4.2.1 Usability 
The system shall allow a normal parent user to complete basic operations (register, try-on, purchase) with no more than 10 minutes of initial learning time.
The system shall support intuitive navigation with consistent layout and terminology across all user roles.
The system shall provide clear error messages for invalid inputs and failed operations.
The system shall support responsive design for both desktop and mobile browsers.
Administrative users shall be able to complete management tasks without requiring specialized technical training.
4.2.2 Reliability 
Availability:
 The system shall be available at least 99.5% of the time, excluding scheduled maintenance.
MTBF (Mean Time Between Failures):
 The system shall have an MTBF of at least 30 days.
MTTR (Mean Time To Repair):
 The system shall be restored to normal operation within 4 hours after a failure.
Accuracy:
 AI Try-On and size recommendation results shall be generated using the latest validated algorithm version.
Defect Rate:
Critical defects: 0 tolerance (e.g. data loss, payment failure)
Major defects: ≤ 2 bugs per KLOC
Minor defects: ≤ 5 bugs per KLOC
4.2.3 Performance
The system must ensure real-time responsiveness in web interfaces:
The system shall generate a Try-On preview result within 5 seconds under normal load.
The system shall support at least 1,000 concurrent users without significant performance degradation
Average API response time shall be less than 2 seconds.
The system shall be capable of processing at least 50 transactions per minute during peak usage.
Uploaded images shall be processed asynchronously to avoid blocking user interactions.
4.2.4 Security
User passwords shall be stored using secure hashing mechanisms.
Access to child data shall be restricted to authorized parents and administrators only.
All payment-related communications shall use secure encrypted channels.
The system shall prevent unauthorized access to administrative functions.
4.2.5 Privacy
Child personal data and images shall not be visible to other users.
Uploaded images shall be used only for Try-On processing purposes.
The system shall comply with basic data privacy principles regarding storage and access control.
